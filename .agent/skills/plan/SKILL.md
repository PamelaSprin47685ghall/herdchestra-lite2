# 实施编排

## 先锁定完成条件

- 写清每个切片的行为、验收、读集、写集与停手条件。先确定消费者能观察什么，不把内部调用当验收。
- 按任务选择简单模式或提交 `todo` 开启完整流程。运行时只检查当前台账和接力状态，不检查阶段顺序；核对当前状态用 `todo` 的 `view`。
- 先跑通最短端到端路径，再加并行、恢复和增强。一个切片只解决一个变更原因；中途应能独立交付，不把修复夹在重构搬家里。

## 只让真实依赖阻塞

- 铺开所有读契约已就绪、写集互斥的切片。共享文件只有一个所有者；接线和注册表（`src/activation/index.mjs`、`src/station/registry.mjs`）归集成者。其他人申请接口，不各自改接线。
- 接口确认、共享写集、依赖的产物是排序依据；按目录名、流程名或“同一批完成”不是。某个产物就绪即放行它的后继。
- 集成者核对消费者与调用顺序，解决接口冲突，最终运行验收。失败时隔离到对应切片，修复真实边界后再集成。

## 开关与切换

- 接线选择等位实现，工单只使用固定接口。参数、运行门禁和模型可见提示必须随同一开关切换；只解析配置、只隐藏工具或只改提示都不算生效。用显式环境验证默认与关闭态，不借本机 shell 的环境。
- 每个跨模块不变式只指定一个所有者。另一端发布事实或提出请求，不写对方状态；有太多反查时，把决定移给已持有事实的一端。
- 持久化迁移验证旧快照和合法的半提交帧。宿主可分两次提交 assistant 帧和 toolResult；临时错位应延迟处理，不当作历史损坏。覆盖拒绝后的清理（如旧 `ownerRetired` 残留），避免错误永久封住工具。
- 对照目标版本的真实工具表、运行路径和提示，确认旧入口没有配置回退或别名。用户显式关闭的能力不得由工单私自重启。

## 历史定位

这一版不下令重跑旧迁移。更早的重构计划：

```sh
git show b33e76c:PLAN.md
```
