# esc-pause-resume-and-silent-stop 验收用例

这些用例是**人工经验测试**，不是单元/集成断言的别名。执行者必须在隔离的 `/tmp` 副本中启动真实的 omp 交互式会话（真实 PTY），按步骤真正按键、真正读屏幕、真正看会话 jsonl，再扮演用户回答最后一步。机器断言只能作为证据，不能替代最后一步。

阈值统一为 85。每条 rubric 单独定义 0–100：

- 90–100：全部要求与列出的非顺利路径都成立，用户愿意为这个体验付费，开发者也愿意签字。
- 85–89：核心体验可用，仅有不超过一个轻微瑕疵；刚好通过。
- 75–84：有一个明确缺陷或一个非顺利路径未证实；刚好不通过。
- 60–74：多个核心行为缺失，需要返工。
- 0–59：数据损坏、假成功、线索丢失或范围失守。
- 每条未实际执行的非顺利路径扣 5 分；越界改源码、把断言结果当成屏幕事实、跳过 `/tmp` 隔离，各算硬失败。
- 判定以 1 分为粒度，不取平均；两位审计者在同一证据上的差值不得超过 5。
- `user_score` 与 `developer_score` 各自独立给出；`final = min(user_score, developer_score)`。任何“wow”同时进入两者，不能只救一边。
- 最少证据：UI 用例要有逐帧屏显/动画前后对比与状态行文本；会话文件用例要有相关 entry 的父链/类型/数量；故障用例要有故障前后的文件痕迹或 warning；恢复用例要有恢复轮实际发出的模型请求与流消息。

## CASE-01

- case_id: CASE-01
- path: `/tmp/esc-accept/01-top-level-esc`
- threshold: 85
- steps:
  1. 复制仓库到 `/tmp/esc-accept/01-top-level-esc`，用 `omp --no-extensions -e ./src/main.mjs` 启动隔离的真实交互会话，不覆盖已安装的插件。确认 `/herd-diag` 无缺失 seam。
  2. 不谈 scope，直接在顶层输入一个会长时间流式输出的请求（例如要求逐段生成长文），等屏幕上出现 `Running… (esc to cancel)` 与持续增长的助手文本。
  3. 只按一次 Esc。立刻记录：转圈是否停止、助手消息是否被替换为宿主的用户中断样式、输入框是否恢复为可编辑空闲态、状态行是否显示空闲。
  4. 保持不动 10 秒，观察是否出现自动重试、第二轮输出或任何新 assistant 消息；打开会话 jsonl 核对本轮只有一条 `stopReason: "aborted"` 的 assistant 消息，且其后没有新的 user/assistant 轮。
  5. 把结果交给扮演用户的 actor，请他回答：“我按了一次 Esc，它是不是真的停住了、而且没有偷偷再跑？”
- expected: 一次 Esc 即停；UI 立即空闲；无自动重试、无续跑、无第二份输出。
- rubric: 100 = 四步全部成立，jsonl 只有一条 aborted 且无后续轮；90 = 停住但状态行文案略滞后；85 = 停住且无重试，UI 空闲确认有一处不直观；84 = 停住但出现一次自动重试；75 = 需按两次 Esc；60 = 按 Esc 后仍在输出；0 = Esc 无任何反应。未做 10 秒静置观察扣 5；未读 jsonl 扣 5；未核对是否新增轮次扣 5。hard fail：把“最终停了”当成“一次即停”。`user_score`/`developer_score` 独立给出，final = min。

## CASE-02

- case_id: CASE-02
- path: `/tmp/esc-accept/02-single-flow-stop`
- threshold: 85
- steps:
  1. 在 `/tmp` 副本启动真实会话，开一个单流 scope：`scope({ begin: { stage: "direct-execution", elder_report: null, time: 600, fission: [{ intent: "长任务", budget: { read: 40 }, permission: "rw" }] } })`，并让该 flow 进入长时间多工具执行。
  2. 在 flow 正在跑工具时按一次 Esc。记录屏幕：正在显示的工具卡片是否立即收敛、转圈是否停止、是否出现用户中断文案而不是继续滚动。
  3. 检查 owner 会话的 `session_stop` 是否没有注入 “This flow is still open” 续跑；检查 flow 的 agent 是否未被重新拉起（jsonl 中该 flow 之后没有新的模型请求）。
  4. 等 15 秒，确认无任何成分流动；随后在输入框输入一句普通消息并发送，确认该 flow 被唤醒并继续工作（内容与该消息相关），而不是重新开一个新批。
  5. 把结果交给扮演用户的 actor，请他判断：“按一次 Esc 是否真的把这条流停住，之后我再说一句它才继续？”
- expected: 单流被完整暂停，无自动续跑，用户消息可唤醒恢复。
- rubric: 100 = 四步全过，暂停与恢复都干净且无重复文本；90 = 暂停正确但恢复后有一处上下文重复；85 = 暂停正确、恢复可用，工具卡片收敛略慢；84 = 暂停后仍发出一次模型请求；75 = 需第二次 Esc 才停；60 = 暂停后自己续跑；0 = Esc 无效。未做 15 秒静置扣 5；未检查 flow 是否被重新拉起扣 5；未发消息验证恢复扣 5。hard fail：把 flow 标成终态 cancelled 后无法恢复。双侧 WTP，final = min。

- threshold: 85
